# PocketCHIP v1.0 hardware acceptance checklist

The ARMv7 Docker simulator (`tests/simulator/armv7/`) and the host gates cover
the software environment: ABI, dynamic linkage, install/update/restore
transactions, permissions and umasks, App Center locking, packaging and
headless SDL startup. The items below genuinely require the physical PocketCHIP
because they depend on hardware, the device kernel, the real filesystem or the
live session. Record each result with the build version, date and evidence; do
not treat emulator results as substitutes.

Run the installation and update through the documented
[device installation](../pocketchip.md) path with the session stopped, and keep the
existing backup so the device can be restored.

## Rendering, display and input

| Check | Why it is hardware-only | What to record |
| --- | --- | --- |
| Hardware renderer selection and Lima detection: `vitrallis --renderer hardware --graphics-info` and `--graphics-test` | Real Mali-400/Lima driver, EGL/GLES2 stack and kernel driver behavior | Renderer name/version, self-test result, screenshot |
| Tearing/VSync observation during boot, scrolling and App Center navigation | Physical display controller and VSync timing | Short video or direct observation, display setting used |
| GPU utilization: open System status while the shell animates and confirm the devfreq reading reflects real GPU load | Lima devfreq and the installed GPU OPP device-tree configuration | Load level shown, matching `/sys/class/devfreq` reading |
| Brightness and display-sleep controls change the physical backlight and recover correctly | Backlight sysfs/DPMS hardware path | Before/after values and restored setting |
| PocketCHIP keyboard, including the Fn layer (Fn+1–0, minus, equals) and punctuation in Terminal | Physical key matrix and kernel keymap | Key-by-key result; any mismatch |
| Touch navigation and activation on every native screen, including confirmation dialogs | Physical resistive touch digitizer | Confirmation defaults (power/install/restore default to Cancel), touch target notes |
| Power, restart and Exit Vitrallis confirmations; restart actually reboots | AXP209 power path and real init | Observed behavior per action |

## Storage, updates and recovery

| Check | Why it is hardware-only | What to record |
| --- | --- | --- |
| Fresh install, normal update and Relaunch Shell on the real installation root | UBIFS/NAND semantics behind atomic renames and `fsync` | Generation directories, `current`/`previous` links, receipt |
| Restore Previous Build on real installed generations, twice (A→B→A→B as available) | Real generation layout and the retained previous build | Versions before/after, user data and apps unchanged, lock released |
| Interrupted update (remove power/battery during download and during pointer switch) | NAND power-loss behavior | Remaining generation boots, marker/journal state, no duplicate installs |
| Storage accounting totals against the real filesystems | Real filesystem usage and app data locations | Totals versus `du` on device |
| Uninstall and reinstall with the documented helper; user documents preserved | Real receipt/boot integration | Preserved files, no orphaned session entries |

## Session and system services

| Check | Why it is hardware-only | What to record |
| --- | --- | --- |
| Stock PocketHome/Awesome integration: menu entry discovery, duplicate handling, focus and keybinding restoration | Real window manager, session and keymap | Menu contents, restored keybindings/focus |
| Session start/stop through the verified supervisor and systemd user manager; cgroup cleanup after killing a running app | Real systemd instance and session policy | Stop/start results, no orphan processes |
| GPU OPP/tracefs provisioning (`platform-setup.py`) and FFmpeg media action (`media-setup.py`) | Device-specific device-tree/KMS paths | Provision status, media playback result |
| Wireless controls against real NetworkManager/nmcli and Bluetooth; Tor startup and fail-closed networking | Real radios and network stack | Interface state, Tor bootstrap, blocked-required-app behavior |
| Timezone/clock change through the authenticated helper | Real system time service | Applied timezone, reboot persistence |

## Published release and live network

| Check | Why it is hardware-only | What to record |
| --- | --- | --- |
| Update from the previous published release to the v1.0 draft, including the new `LICENSE`/notice assets in the release listing | Live HTTPS, GitHub metadata and the real updater | Update state transitions, no asset-list error, version after Relaunch |
| App Center Refresh, install, update and remove against published apps, including app-local Python dependency provisioning | Real device Python/venv, network and app payloads | Installed versions, app launch, removed files |
| Long-running stability: repeated boot cycles, background apps, Terminal/Notepad/Files round trips, storage fill near capacity | Real memory, CPU, NAND endurance and thermals | Duration, memory samples, observed failures |

## Out of scope for this checklist

- Re-verifying emulator/host results (ABI, unit/integration tests, packaging
  bytes) on the device; the simulator already covers them.
- Kernel, device-tree or OS image changes: v1.0 does not ship an OS image.
- Performance claims beyond "slow hardware remains responsive"; record observed
  stalls rather than absolute numbers.
